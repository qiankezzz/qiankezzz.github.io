# 个人主页项目作品文章撰写说明

这份说明供协助撰稿的智能体使用。目标是在现有个人主页中，为**经过本人选定并允许公开**的项目各写一篇独立文章。文章应说明真实问题、本人承担的工作、实现方法和可核实的结果，让读者看懂项目，也方便本人解释代码与过程。

## 开始前需要的材料

请先向本人索取每个项目的以下信息。缺项应提问或明确标为待补充，不得自行编造。

| 信息 | 需要确认的内容 |
| --- | --- |
| 项目名称与时间 | 可以公开的名称、起止时间或阶段 |
| 背景与目标 | 解决什么问题，面向谁，完成标准是什么 |
| 本人角色 | 独立完成还是团队合作，具体负责哪些部分 |
| 技术与实现 | 使用的语言、框架、模型、工具及其用途 |
| 难点与选择 | 遇到的实际问题，为什么采用某种方案 |
| 验证与结果 | 测试方式、可公开的指标、演示或交付状态 |
| 展示材料 | 可公开的截图、代码仓库、演示链接及使用授权 |

原始简历只适合作为线索，不能直接整段复制。简历里的数字、项目成果和职务描述也需要本人复核，尤其不能把团队成果全部写成本人独立成果。

## 隐私与事实边界

- 公开身份统一使用 **xte12329**；GitHub 链接使用 `https://github.com/qiankezzz`。
- 不写真实姓名、手机号、私人照片、住址、学号、身份证号、未经同意的同事或导师姓名。
- 不把原始简历、截图中的个人资料、内部界面、未公开代码或数据复制进仓库。
- 图片只使用本人确认有权公开的材料；上传前检查画面、文件名、EXIF 和替代文本。
- 不编造准确率、性能提升、用户量、奖项、论文状态或上线情况。没有证据时用定性说明，并标明验证范围。
- 技术名词要与实际工作相符。能说明“我做了什么”，就不要只罗列技术栈。

## 推荐文章结构

一篇文章建议控制在 600–1200 字；复杂项目可更长，但每节要有具体信息。

1. **项目概览**：一句话说明项目做什么、解决什么问题，以及本人负责的范围。
2. **问题与约束**：用户或场景、已有条件、时间或数据限制。
3. **我的工作**：按工作步骤说明实现，而非只列技术名称。
4. **关键选择**：一两个重要设计或算法选择，说明原因和代价。
5. **验证与结果**：写测试方法、观察到的结果和目前局限。若有数字，注明口径。
6. **复盘**：这次实践学到了什么，下次会如何改进。
7. **参考与链接**：只放可公开的代码、演示、文档或图片来源。

示例开头（方括号内容必须由真实材料替换）：

> [项目名称]面向[具体场景]，目标是[具体问题]。我在项目中负责[明确职责]，使用[技术及用途]完成[可验证的工作]。本文记录其中的实现选择、测试结果和仍待解决的问题。

## 在本站中的实现方式

本站是 GitHub Pages 静态站，主页入口为根目录 `index.html`，通用样式为 `styles.css`，文章样式为 `article.css`。请参考 `writing/learning-journey/index.html` 的页面结构和导航，保持深色主题、语义化标题、手机布局与返回首页的链接。

建议每个项目放在 `writing/projects/<英文小写短名>/index.html`。从该目录引用根目录资源时使用 `../../../styles.css` 和 `../../../article.css`。项目配图放在 `assets/projects/<英文小写短名>/`，使用相对路径。文件名不要含真实姓名或其他私人信息。

每写完一篇文章，请交付：

1. 文章页面及必要的公开图片。
2. 一份简短的事实核对清单，列出每项重要数字和成果的证据来源。
3. 需要本人补充或确认的问题。
4. 本地预览结果：桌面 1440px 与手机 375px 无横向滚动，图片正常加载，导航与链接可用。
